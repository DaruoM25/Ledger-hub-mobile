Approche TDD hybride : aucune fonction métier ni composant UI n'est validé sans son test associé.2. Logique pure : utilise kotlin.test pour tester la logique de domaine (calculs de montants, validation, parseurs).3. UI Testing : utilise compose-ui-test en ciblant les éléments via semantics (testTag ou contentDescription). Vérifie les transitions d'état (états désactivés, affichage d'erreurs).4. Déterminisme : mocke toutes les dépendances réseau et locales pour des tests rapides et fiables.
